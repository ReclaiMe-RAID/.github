# ReclaiMe — rebuild view for an array you administer

ReclaiMe holds a lab desk for a volume on an array you administer: the RAID rebuild view, the volume recovery, and a short note the next operator can read. Extra arrays wait for their own title.

## Session Card

| Slice | What you do in ReclaiMe | What remains |
|-------|------------------------|--------------|
| Arrival | Open ReclaiMe and name today's lab desk | A titled rebuild view |
| Focus | Keep only live volumes on the ReclaiMe board | A short layout list |
| Check | Read ReclaiMe RAID rebuild view before a large recovery | A confirmed lab desk |
| Handoff | Mark finished volumes inside ReclaiMe | A note for the next operator |

## How ReclaiMe Sits

ReclaiMe does not replace a guess about missing disks, a rebuild of an array you do not administer, or a layout on someone else's RAID. It sits beside them as a named lab desk for one job: which rebuild view is live, which volume recovery still matches your own array, and what the next operator should read.

A first visit should be one short rebuild view on an array you administer, then the same ReclaiMe lab desk the next day. That is enough to see if the named layout holds.

## Traffic Light

| Signal | On the ReclaiMe board | What you do |
|--------|----------------------|-------------|
| Green | Named rebuild view, short live volume list | Continue the same volume recovery |
| Amber | Two arrays mixed on one layout | Split the view before a large change |
| Red | No title, no note, a guess about missing disks | Stop and name the lab desk first |
| Clear | Handoff written, live views few | Close ReclaiMe and leave the lab desk |

## Open Order

1. Open the last ReclaiMe lab desk, not a new empty rebuild view.
2. Confirm the array is one you administer, then read the layout and the last handoff.
3. Finish one visible volume recovery inside ReclaiMe on owned disks.
4. Write what changed, then close with fewer missing-disk guesses than you found.
5. If the layout feels crowded, drop anything that belongs to a different ReclaiMe job.

## Desk Fit

| Who | What ReclaiMe holds |
|-----|--------------------|
| Lab desk | RAID rebuild view, volume recovery, and the own array you keep |
| Shared PC | One ReclaiMe profile per operator |
| Support | A repeatable ReclaiMe layout for the same array |
| Shop RAID | Named rebuild view on disks you own |
| Close-out | Volume recovery waiting for the last layout check |

## After a Week

A week in ReclaiMe is not a larger pile of missing-disk guesses. It is the same title, a shorter live volume list, and a note that still makes sense before the next rebuild view.

Leave ReclaiMe with a quieter lab desk than the one you opened. The next visit should start on that named rebuild view, not on a guess about disks you do not own.

## Sign-off

- [ ] The ReclaiMe workspace name is short enough to scan
- [ ] Only arrays you administer sit on the lab desk
- [ ] A second operator can read the rebuild handoff
- [ ] The last ReclaiMe volume recovery still opens after a restart

## Field Note

ReclaiMe is easier to trust when the lab desk stays on an array you administer. Name the rebuild view, keep the live volume recovery, finish one visible layout pass, and write what changed.

The same loop fits a shop RAID, a close-out, or a shared PC. Open the last ReclaiMe desk and continue. Do not rebuild an array you are not authorized to recover.
